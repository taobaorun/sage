# 验证与交付

## 两种证据分开收集

| 证据 | 能说明什么 | 不能替代什么 |
| --- | --- | --- |
| 计算与状态检查 | 公式、边界、阶段互斥、取消语义 | 实际渲染与可读性 |
| 真实浏览器操作 | 翻页帧、焦点、遮挡、响应式、可用性 | 专业数据正确性与完整物理验证 |

变更只涉及文字或材质时，不为它写镜像实现的测试。涉及翻页、计算或暂停状态时，优先写能区分错误版本与正确版本的行为检查。

## 自动检查

随附的 `scripts/check-book-core.mjs` 不需额外 npm 包，检查四阶段姿态、前后方向、边界、页码和纸面坐标往返，并用故意错误的重叠和 UV 方向作负对照。

接入具体项目后，补充真正受影响的检查：

- 正反向遍历阶段，覆盖边界前后一个小时间量；活动页存在时不出现可见模型。
- 真实场景调用是否执行 `visible=false`，而不只是纯函数返回了正确标志。
- 快速连点最后请求胜出，取消完成旧 Promise，临时纹理解绑并释放。
- 纸面点击：不同画幅、缩放、视角和 DPR 下，屏幕投影仍命中印刷区域。
- 公式的边界、单位、关系和非法输入；暂停保持相位，改速度不跳相位。
- 重复进入章节与切换参数后，几何/纹理数量不持续增长。

负对照应触发同一断言失败。例如故意让活动页与模型同时可见，确认重叠检查确实拒绝它。仅确认计时器能走完不算防穿模证明。

## 浏览器检查

新书或视觉保真改动先执行 [视觉基准](visual-baseline.md) 的代表跨页验收。测试采样通过、产出规划文档、加载 Three.js 名称，都不足以证明已经达到立体书效果。

遵守用户指定的浏览器和当前工具文档。使用环境支持的隔离浏览器或内置浏览器，不接管个人浏览器配置。某种工具不可用或被用户禁止时换允许的工具，不绕过限制；无法运行时诚实报告验证范围。

以任务需要选择场景，不要求每次跑完整产品：

1. 首次进入：封面文字密度、可发现入口、初始阴影和布局稳定。
2. 正反翻页：捕获多个实际帧，观察文字正反面、模型、纸页、封面与翻盖。
3. 内容：展开/收起、翻页后收起、长文滚动、键盘、Escape 与焦点恢复。
4. 模型：默认运行是否符合章节，暂停、重置、改参数、改视图是否保持预期状态。
5. 布局：宽屏与一个窄屏；必要时补短横屏、夜间、减少动态/透明偏好和 WebGL 降级。

参考站点中的 iframe 应先确认真实地址及访问权限，再通过支持的导航查看。不要把无法访问的参考站当成已验证，也不要把一次截图概括为“永不穿模”。

真实浏览器控制保持在指定工具内。只读页面评估用于观察 DOM 和布局，不能拿来绕过交互 API、修改页面状态或控制隐藏应用对象。截图输出和构建检查可使用正常文件工具。

保存能解释变更的截图，报告有无观察到问题；没有复现的缺陷注明“做了针对性处理，当前场景未复现”，不要把推测包装成根因确认。

## 构建和离线版本

运行项目已有且相关的检查与构建。三维库体积告警不自动意味着需要拆包重构；只有出现实际目标或回归才扩大性能工作。

用户要离线单文件时，将必要代码、样式、模型和纹理嵌入，检查动态加载、外部字体和网络依赖。在环境允许时用 `file://` 实测；仅浏览器 HTTP 预览不能证明本地文件协议可用。说明未内嵌的依赖，不用“单文件”冒充完全离线。

## 发布边界

先识别目标站和当前访问范围。已有站点只更新它的内容，不新建同名站、不修改共享；本地交付则不发布。

如果本次使用 Sites，调用当前可用的 Sites skill 与工具完成源码同步、构建、保存和部署；让它拥有凭据和发布细节，不把此案例的项目 ID、账户、token、固定域名或临时凭据流程写入新产品。其他平台使用对应的既有流程。

发布返回非终态时跟踪同一次部署。超时或结果不明，先查已保存版本与部署记录，再决定是否重试；不能盲目重复创建。权限/访问拒绝应按错误处理，不照搬过去某次上传失败的应急办法。

成功状态与可访问地址才能支持“已发布”。只完成本地构建就交付本地结果并明确限制。关闭此次创建的临时标签页和预览进程，保留用户原有浏览器会话。
