# 视觉与空间基准

## 先锁定呈现层级

本 skill 默认目标是汽车原理书那样的真实空间立体书。迁移主题主要替换内容和模型；书本、相机、灯光与交互骨架应保留。可更换配色、纸张风格和装饰，不应静默降级成 CSS 双栏卡片、图片幻灯片或答题网页。

使用已有真实 3D 工程，或从随附的 three-book-starter 起步。其他引擎可以使用，但需要实现相同的可观察能力。轻量 CSS 书、二维课件是另一种交付规格：仅在用户选择它或明确同意降级时采用；设备失败时的静态降级不算主效果完成。

首次制作或比较效果时，用图像查看工具读取这些实际参考图，不能只根据“纸张”“玻璃”等文字猜风格：

- [封面与桌面](../assets/visual-reference/car-cover.jpg)：书的占比、俯视角、封面厚度与简洁导航。
- [打开的跨页](../assets/visual-reference/car-open.jpg)：纸上模型、同一光照、接触阴影与实体书边缘。
- [窄屏展开阅读](../assets/visual-reference/car-reading-narrow.jpg)：让位后的书本与非模态正文共处。

这些图记录原汽车案例的不同迭代阶段，用于观察构图与空间质量；不要复制其中车型、章节文字，也不要把某一阶段的颜色或透明度当成固定参数。

[当前模板的实际运行截图](../assets/visual-reference/starter-open.jpg) 展示中性摆模型接入后的空间效果，用于确认复制模板后没有退回平面卡片实现；具体新主题仍需自己的代表跨页验收。

## 必须看得见的能力

| 维度 | 通过标准 | 不能据此宣称通过 |
| --- | --- | --- |
| 书本体积 | 封面、书脊、页堆有厚度；翻开围绕装订轴运动 | 给两个 DIV 加渐变和 box-shadow |
| 统一空间 | 书页和主体同一相机；改变视角产生一致透视、遮挡和落地关系 | 单张插图做 rotateX 或 scaleY |
| 光照 | 模型体积有明暗，纸面接收模型投影，接触处稳定 | 为图片卡片加一圈 CSS 阴影 |
| 页面连续性 | 活动纸页正反面来自真正的旧/新内容快照 | 翻动时只显示章节标题和口号 |
| 内容主体 | 至少代表跨页的主体有真实深度与可解释交互 | 切换两张照片却声称连续变换观察视角 |
| 画面构图 | 书是主体，视角略俯视；工具浮于场景，长文按需展开 | 书退成文档流中的一张大卡片 |
| 窄屏 | 保持书本空间关系，调相机与可用区域，文字可展开读 | 把左右页拆成上下文章，仍声称同一立体效果 |

这些标准不要求每页都是机械模型。儿童安全、自然故事等主题可以有选择题、旁白和插图；需要空间理解的部分应在空间里表现。例如盲区可用同一辆车和人物模型，移动相机展示遮挡；不能将换图自动当作等价的司机视角实验。

图片适合封面纹理、纸面插图、背景或一个纸偶的外观。整幅课件 JPEG 原样放在倾斜矩形卡上，不等于完成一个空间场景。

## 先验收切片，再扩章

先完成封面、一个代表跨页和往返导航。保存相同画幅下的封面、打开状态、翻页中间帧及窄屏截图，对照以上标准；有参考截图时并排检查书的占比、视角、模型高度、阴影和文字密度。

代表跨页选最能验证空间能力的内容，而不是最容易换图的一页。若这一页只有一张图片和两个按钮，先修正骨架，不要复制成十几章。

纯逻辑采样只证明时序；方案演练只证明理解了要求。两者都不能替代可运行的代表跨页，也不能据此宣称达到基准视觉质量。

## 模板使用

从 skill 的绝对路径运行，目标目录必须尚不存在：

```sh
node <skill-dir>/scripts/create-book.mjs --out <new-project-dir> --title "新书名"
cd <new-project-dir>
npm install
npm run dev
npm run check
npm run build
npm run export:standalone
```

生成的是本地 Vite + Three.js 项目，不包含托管身份。`dist/interactive-book.html` 是捆绑了渲染库、样式与程序材质的单文件；添加远程图片或其他资产后需重新检查离线完整性。

替换入口：

- `src/content.js`：跨页短文、展开阅读、实验参数和读数。
- `src/lesson-math.js`：主题计算，与模型和界面共享。
- `src/demo-models.js`：替换为目标主题的模型工厂；保留 `root/update` 约定及点击元数据。
- `src/book-viewer.js`：负责书本/相机/照明/翻页/资源，不把章节业务塞进此文件。
- `src/style.css`、`src/main.js`：保留浮动导航和阅读面板，按主题微调视觉与控件。

默认摆和杠杆只是骨架验证示例；改完主题后不要遗留示例公式、按钮或阅读文本。不要将启动器文件夹直接作为已完成的主题书交付。

## 一次真实失败带来的校正

曾有成品复用了四阶段时序，但整书没有 Canvas、3D 相机或实体模型；主体是嵌入的 JPEG 卡片，所谓“司机视角”通过替换图片实现，翻页面只有标题。它可以通过阶段检查，却与汽车书的效果明显不同。

这说明只写“立体”“毛玻璃”“不穿模”不够。先继承可运行的场景骨架，再更换主题；用真实截图和交互验收空间效果，而不是只检查有无关键词、依赖名称或测试通过标记。
